# 功能逻辑说明

**语言 / Language:** 中文 | [English](README_LOGIC_EN.md) · [返回 README](../README.md)

## 三部分各自负责什么

React 界面负责配置编辑、状态和提示；Rust 桌面壳负责配置、窗口、进程、地图导入和更新；Python 自动化引擎负责截图、识别、任务判断与键鼠输入。界面不决定游戏动作。

“游戏启动”“登录组件”“自动化引擎”是不同入口。普通启动游戏不改变游戏窗口布局，也不自动开始对局任务。登录组件独立处理登录流量，代理就绪不等于账号认证成功。

## 游戏启动与登录组件

启动页自动定位正式服 `dwrg.exe`，也可在齿轮面板手动选择。不能选择发烧平台、安装器或无关程序。启动时先检查登录组件更新并等待代理就绪，再直接启动游戏。

完整组件更新使用 [KKeygen/idv-login 的最新正式发布](https://github.com/KKeygen/idv-login/releases/latest)，不再限制助手预先适配的版本。配置会优先扫描已有有效运行库；找不到时可以按选定来源下载官方组件。手动选择的是运行库或其 `python-embed/python.exe`，不是下载的安装器。助手校验下载并解包，不静默执行第三方安装器脚本。

首次登录、登录凭证过期等情况仍需本人操作。组件自己的账号数据位于 `%LOCALAPPDATA%\IdentityV-Assistant\login-data\idv-login`；助手不读取或显示账号凭据。官方组件会配置登录证书和 URI 协议，因此它与仅使用视觉识别的自动化引擎有不同的系统作用。

组件检查在点击启动游戏时进行，并保留手动检查入口；不会在助手启动时自动检查组件。0.2.0 起跳过所有模块热更新，提供官方最新完整组件，并按发布附件的大小和 SHA-256 校验。点击一次更新后完成下载、校验和配置。启动时检查失败会用已安装组件继续启动并显示短提示；手动检查仍显示详细错误。只读检查可关闭，关闭后不再自动继续启动。

只管理本助手启动且身份可确认的组件。已有独立组件时先由用户关闭，助手不会接管或按程序名批量结束进程。退出助手或安装更新会关闭自己拥有的代理并尝试恢复原 URI 注册；已打开的游戏保留，但会失去这份代理。

## 自动化任务与队列

| 任务 | 行为 |
| --- | --- |
| 登录进大厅 | 双帧确认已知登录画面，选择平台、处理弹窗并等待归宿；超时可配置为 30–900 秒，默认 300 秒 |
| 黑杰克 | 从归宿、匹配、准备、对局或结算等已知阶段接管，按识别到的角色执行动作，返回归宿后计一次循环 |
| 监管者匹配 | 通过日记推理进入匹配，使用共享的监管者对局逻辑 |
| 监管者排位 | 通过排位模式和传统排位进入对局，与匹配共用战斗判断 |
| 捉迷藏 | 选择坏孩子，按确认的存活阶段同时执行移动与视角动作，并处理固定、淘汰和返回流程 |

勾选的任务按列表顺序执行；启动任务时会自动启动尚未运行的引擎。对局任务的无限循环默认关闭。暂停会释放按住的输入，并排除暂停期间的计时；恢复重新截图识别，而不是继续盲发旧动作。

0.1.9 起，单个任务或新队列启动前检查游戏窗口、响应状态和画面捕捉；失败会阻止启动，提供重新检查及捕捉诊断入口。实际启动沿用引擎窗口布局，分辨率或前台差异只提示，不自动切换捕捉后端。循环下一局不会重复检查。失败后的重新检查通过时，可点击“启动原任务”继续，检查本身不会自动启动。任务页的“停止任务与队列”会停止当前任务并清空队列。概览页的任务进度卡显示当前阶段、任务／阶段有效用时、暂停原因与下一步提示；暂停时间不计入有效用时，引擎重启后不续接旧计时。

普通不可恢复错误和登录超时会暂停当前任务、保留队列。四个对局任务遇到前台丢失或捕捉失败时会尝试恢复窗口；恢复持续超过 300 个有效秒后停止当前任务并清空队列，引擎保持运行。点击任务行“停止”也会清空后续任务。已识别的匹配和结算等待与未知画面超时不是同一条件。

监管者任务在识别到游戏计时至少六分钟后尝试投降；如果有效 OCR 连续缺失至少 30 秒，也可在本地有效战斗计时达到六分钟时回退判断。实际点击仍受画面确认约束。具体阶段和动作时间表见英文技术文档 [state-machine.md](state-machine.md)。

## 捕捉、输入与窗口

默认捕捉后端为 WGC，按窗口句柄读取客户区。只有显式配置为 `auto` 时才按 WGC、DXcam、MSS 顺序尝试回退；不同后端对遮挡、副屏及显示器有不同限制。

**截图可以读取被遮挡窗口，不代表游戏可以接受后台操作。** 任务使用真实 Windows SendInput，发送前核对前台窗口，并追踪按住的键鼠以便清理。没有默认 dry-run 模式。

显式开启引擎（包括 F3）或启动任务会启用游戏窗口布局，默认 1600×900、右上角。单次诊断临时启动的引擎不启用布局。停止时释放输入并尝试恢复原窗口；监督层最多等待十秒清理。正常启动游戏保持原窗口位置和样式。

## 加页手记与地图格式

导入 ZIP 时可按 Ctrl／Shift 多选；同一批次逐包处理，失败不会阻止后续包。结果使用顶部提示条：停留两秒，再用半秒淡出并收起占位。鼠标悬停或键盘焦点保留提示，也可手动关闭。页面滚动或离开手记后，完成提示仍可见；详细结果同时进入日志。

只导入 `pack.json` 引用的 PNG/JPEG/WebP 图片，不覆盖已有同名 `packId`，不修改源 ZIP，不读取其他软件的数据目录。支持根目录或嵌套目录的 `pack.json`，不支持旧 `manifest.json`。路径穿越、链接、重复文件和过大解压会被拒绝；当前限制包括单图 20 MiB、包 512 MiB、描述文件 2 MiB、20,000 项和 16 层路径。

最小示例，图片 `maps/1f.png` 必须真实存在于包内：

```json
{
  "packId": "example-s0-hard",
  "packName": "示例地图",
  "seasonId": "s0",
  "difficulty": "hard",
  "maps": [
    {"index": 1, "category": "lf", "floors": {"1": "maps/1f.png"}}
  ]
}
```

门型为 `lf`、`rf`、`lr`、`triple`、`td`；`floors` 表示纯净图，另可用 `display` 提供速刷图；S0 楼层键使用 `1`、`2`、`b1f`，旧 `3` 按地下室兼容读取；S1 使用 `1`、`2`、`3`，分别表示地下1、2、3层。图片路径使用 `/` 分隔。

赛季、难度、门型和显示模式静默保存；楼层与筛选折叠状态在每次进入时重置为识别层（S0 一楼、S1 地下1层）、展开。地图详情和预览均在助手窗口内，不是游戏悬浮层；Esc 先退出预览，再返回列表。

0.2.0 内置 `s0_hard_11-05.zip`（29 张）和 `s0_nightmare_11-05.zip`（26 张），每张保留纯净及速刷层。启动时静默补齐缺失内容，明细写入运行日志。确认与原附件完全一致的旧包先移入 `journal/backups` 再退出活动目录；自定义内容不覆盖并优先展示，冲突写入日志。

另内置 **S1 磷光症** 困难 14 张、噩梦 15 张地图，只有地下1至3层纯净图。切换 S1 后隐藏门型、禁用速刷；切回 S0 恢复之前的显示选择。旧版导入时保存为 `b1f` 的 S1 第三层仍可读取。

### 识别地图（0.2.0）

游戏或助手前台按 **L** 切换助手正在展示的地图楼层；不操作游戏或抢焦点。S0 噩梦按地下室→1F→2F 循环，困难略过地下室；S1 按地下1层→地下2层→地下3层循环；缺少图片的楼层也会略过。助手输入框打字时不触发。

**S0：**先选择纯净／速刷，在游戏内展开一楼地图，再点击“识别一楼地图”或在游戏前台按 **P**。截图先核对楼层标志：`1、2` 为困难，`-1、1、2` 为噩梦；看不清或被遮挡时停止并提示重试，不使用手动难度兜底。检测结果同步到手记难度选项；手动难度仍用于浏览。P 可在设置中更改，保留游戏原按键，不打开游戏地图、不激活助手。识图中再次按 P 会取消旧进程，等待退出后立即重新截图，连续触发只执行最后一次；不等待旧匹配完成。自动任务执行或等待启动期间不能识图，先暂停或停止任务。

**S1：**先手动选择困难／噩梦，在游戏内打开地下1层地图，再点击“识别地下1层地图”或按 P。S1 两种难度都使用地下楼层，不套用 S0 楼层标志判断，固定匹配所选难度的地下1层。

识图固定搜索当前赛季的识别层模板（S0 自动难度一楼，S1 手选难度地下1层），忽略门型筛选。速刷模式只列出有一楼速刷图的地图，不自动改用纯净展示图。地图身份包含门型和编号，因此不同门型的“地图 1”会分别显示。通过几何检查的候选按匹配结果排序，界面最多显示前 4 张，不显示准确率；完整结果仍保留在运行日志和诊断记录中。识图按钮下方的“自动进入最匹配地图”默认关闭，开启后识别成功直接打开第一名的全窗口预览，不激活助手或抢走游戏焦点。该选择会保存；自动进入不代表已经确认地图正确。

进入地图后可拖动黑色地图区域，也可聚焦地图后用方向键移动（Shift 加快）。所有地图和楼层共用上次保存的位置，重启后保留；换图或调整窗口大小时按相对位置恢复，并限制在四周至少 16 像素的安全范围内。关闭、楼层和位置按钮始终位于地图上方；关闭按钮左侧可选左上、右上、居中、左下、右下，默认居中。重复点击当前预设不会取消选中；手动拖动或方向键移动后取消预设选中，并保存自定义位置。关闭预览后可返回候选列表换图。

识图单独启动只读进程，不启动自动化服务、不改变游戏窗口布局、不发送游戏输入。仅使用 WGC 窗口截图，不回退到桌面截图；定位后先在匹配进度下方居中显示暂定区域，限制在两条分隔线内；匹配发现更可靠的区域时更新图片。结果中的“查看识别区域”默认折叠。每次识图的诊断证据保存在本机，保留范围见下文。可取消识图；改变识别条件或离开手记会取消旧请求，迟到结果不会覆盖新选择。未找到可靠候选时清除旧结果，提示在一楼打开地图后重试。超时上限为 120 秒，图片解码上限为 16,777,216 像素。

同一次识图复用截图的归一化边缘与缩放结果，精细匹配缓存最多 32 MiB，结束或取消后释放；这一复用不会改变搜索缩放范围或匹配分数。地图自动定位与几何阈值属于启发式判断：探索太少、遮挡、复杂 HUD、游戏缩放和相似结构可能产生漏检或相似候选。离线生成图片及模板局部测试不等于真实游戏识别率；请核对候选和识别区域后使用。

区域尺寸检查同时作用于初选区域和裁去背景后的可见结构，短边不足 64 像素时不进行匹配，避免小图标借助周围空白通过检查。小地图探索范围太小时，可展开地图、放大或继续探索后重试；这一检查不能排除所有较大的 HUD 误识别。

## 本地数据、日志与诊断

```text
%LOCALAPPDATA%\IdentityV-Assistant\
  config.json                 设置和启用任务
  logs\YYYY-MM-DD.jsonl       引擎与界面完整事件
  debug\captures\            手动捕捉的调试截图
  debug\failures\            自动保存的失败截图
  debug\recognition\<id>\   每次识图的报告与图像
  backups\                   恢复设置前保留的配置备份
  journal\packs\<packId>\    已导入地图
  login-data\idv-login\      独立登录组件的数据
```

日志保留最近七天，界面仅显示当前会话，最多保留 99,000 条，每页 1,000 条；清空页面不删除磁盘日志。普通模式只简化显示，开发者模式可展开同一份脱敏记录的详细字段并搜索。识图触发、独立进程启动、截图、定位、匹配、候选、耗时、取消和失败都写入运行日志，图片二进制及凭据不写入文本。分享日志或截图前自行检查是否含个人信息。

捕捉诊断可以发现窗口、手动截取画面和检查模板。诊断输入需要单独启用，任务运行或暂停期间不可用。

失败截图默认开启，可在设置中关闭。任务因错误暂停或窗口恢复超时停止时，每次失败最多保存一张最近成功的 WGC 游戏窗口画面；没有可用画面时跳过。自动保存不使用 DXcam／MSS 屏幕区域图像，避免将遮挡窗口保存进去。文件名及日志保留实际拍摄时间，可能早于失败时刻。最多保留 20 张、合计 100 MiB，单张上限 20 MiB；此数量限制只用于失败图片；所有助手生成的截图另按三天期限清理，手动放入的其他文件不清理。截图仅保存在本机，可能含昵称或聊天。

### 设置备份与恢复

设置页底部“识别与诊断”中的导出功能可备份助手偏好和任务参数，不含账号、地图或日志。导入只接受本功能的版本化 JSON，最大 1 MiB，校验字段、类型、版本及快捷键；不可用的游戏路径保留本机现值。在居中弹窗查看“当前／应用后”差异，再点击“确认应用”；没有差异时无需应用。运行、暂停或排队任务期间禁止恢复；空闲引擎会停止，下次启动读取新设置。恢复前在 `backups` 保存原配置，写入采用原子替换，桌面设置应用失败会尝试回退。导出文件应存放在助手数据目录之外。

设置读取失败时禁止编辑并提供重新加载；保存失败会持续标记“尚未保存”并提供重试。操作结果提示停留 2 秒，再用 0.5 秒淡出，悬停或键盘聚焦可保留；需要确认的弹窗不会自动关闭。

### 诊断包

默认文件名为 `IdentityV-diagnostics-YYYY-MM-DD-HHmmss-SSS.zip`，使用本地日期、时间和毫秒，便于区分多次导出。

点击“导出诊断包”后先选择会话，再预览，最后自行选择 ZIP 保存位置，不自动上传。不勾选历史会话时只包含本次助手启动会话；也可追加多个历史会话，每次打开重新选择。日志覆盖全模块（启动、设置变化、任务、更新、地图操作及识图）。每次识图独立保存在 `recognition/<识图编号>/flow.redacted.json`，包含条件、阶段、定位检查、每张模板的匹配评分与通过／排除原因、耗时及取消原因；不逐条记录所有滑动搜索位置。必要运行环境和脱敏设置为预览时的当前状态，不冒充历史快照。排除账号目录、凭据、私钥和组件运行库；分享前仍需检查内容。

“诊断包包含截图”首次默认关闭，选择后自动保存，并统一控制当前和所选历史会话。开启时加入仍在三天保留期内的完整窗口 `full.png`、定位裁剪 `region_*.png`、处理图 `edges_*.png`／`mask_*.png`、实际参与识图的模板边缘 `template_*.png`、最终区域 `region.png`，以及对应会话的调试／失败截图。新一次识图不会覆盖前一次；取消或失败保留已经收到的证据。截图不做文字脱敏。三至七天前的会话只有日志和识图文字报告；无会话编号的旧版日志按日期单列，不猜测关联图片。

仅当前会话的 ZIP 不超过 **100 MB**；追加历史会话后不限制总大小。日志和报告优先，剩余容量按时间从新到旧纳入完整图片组；超限或缺失的图片组不部分混入，不降低原图清晰度。预览及 `manifest.json` 列明省略项与原因。预览将内容流式写入临时 ZIP，冻结本次导出；之后产生的操作需返回选择再预览。保存或关闭后释放临时文件。截图在本机保留三天，日志和识图报告保留七天；应用运行时清理过期的自有文件，锁定文件稍后重试。“设置 → 识别与诊断”提供日志、截图目录入口。

识图反馈按钮已移除，已有记录中的反馈仍随对应证据保留。开发者可用 [离线重放命令](development_zh.md#诊断包离线重放)复测同一截图与模板证据，不操作游戏、不自动修改识别阈值。

## 更新与验证范围

助手更新和登录组件更新分开管理。助手启动检查可关闭；发现版本后先展示说明，用户确认后才下载或安装。直连与代理均执行签名、签名内版本、安装包地址、SHA-256 和大小验证。默认使用 GitHub 直连，可手动切换三个代理源；0.1.8 已删除自动测速。下载速度与剩余时间根据最近五秒的实际字节变化估算，停滞时显示待估算。

完整组件更新复用助手下载进度，显示大小、百分比、速度和预计剩余时间，区分下载、解包、校验、配置和恢复代理。操作期间不可关闭更新弹窗、切换页面或退出助手；下载和校验可取消，配置及回滚期间不可取消。完成或取消后可关闭，最小化仍可用。

助手安装包不包含登录组件补丁，也不会应用历史热更新。完整组件下载到独立版本目录，不覆盖外部安装，保留账号数据和旧组件；切换配置或恢复助手持有的代理失败时尝试回滚。提醒仅按完整版本忽略，新版本仍会提示，手动检查始终可用。

仓库迁移、历史版本兼容与发布步骤见 [更新与发布](updates.md)。测试验证截图识别、逻辑、模拟 IPC 和打包完整性；0.1.9 和 0.1.10 的验证未覆盖新程序安装、原生运行、真实账号登录或实际对局。
